# ADR-0012. Веб-панель SMS-рассылок: без подтверждения, все видят всё, вход через учётки сайта

- Статус: **принято** (2026-11-17, решение Свята)
- Уточняет [ADR-0010](0010-single-web-admin.md) §2–3 на переходный период. Номер 0011 занят ADR о YCLIENTS (PR #53).

## Контекст
В клинике поставили MAUI-программу «по заявкам» (#49–#52). Сотрудникам непонятно, что такое «заявка» и кто её
«одобряет»: в клинике нет отдельного человека, который проверяет чужие рассылки. Нужна веб-панель в админке сайта,
понятная без обучения. Прототип согласован со Святом 17.11 (кликабельный, с мобильной вёрсткой).

Полный перенос учётных записей в `Users` сервера (ADR-0010 §2) требует миграции и смены паролей у всех — сейчас не до неё.

## Решение
1. **Подтверждения нет.** Слово «заявка» в интерфейсе не используется. Рассылка проверяется в мастере перед запуском:
   сколько получат, кто и почему не получит (нет согласия, «СТОП», нет телефона), сколько SMS, когда закончим.
   Сервер создаёт рассылку сразу одобренной (`approveAutomatically`). Остановить можно в любой момент: «Пауза»
   (статус `Paused`, очередь снимается) и «Остановить» (остальным не уйдёт).
2. **Все сотрудники видят всё.** Ролей в панели нет: каждый, кто входит в админку сайта, может писать пациентам,
   запускать рассылки, менять шаблоны и телефоны.
3. **Вход — общий, учётками сайта** (`site.Editors`; в меню раздел переименован в «Сотрудники»). Сайт ходит в сервер
   от имени панели:
   - сервер при запуске создаёт ключ `%ProgramData%\ClinicHub\panel.key` (настройка `Panel:KeyFile`); папку установщик
     закрывает от обычных пользователей Windows — читают только SYSTEM, администраторы и LOCAL SERVICE (обе службы);
   - сайт шлёт заголовки `X-Panel-Key` и `X-Panel-User` (логин сотрудника — для журнала согласий);
   - сервер принимает ключ **только с этого же компьютера** (loopback), сравнение за постоянное время; действует
     служебный пользователь `web-panel` (роль Admin, входить по паролю не может).
   Схема `JwtOrPanel`: есть заголовок ключа → проверка ключа, иначе JWT, как раньше (MAUI и SmsAgent работают без изменений).
4. **Автоматические рассылки — внутри «Рассылок»**, создаются тем же мастером («Когда отправлять: один раз /
   автоматически по событию»): после визита, давно не был (сценарии ADR-0008), день рождения (авто-правило).
5. **Согласия в карточке пациента — два:** обработка персональных данных (152-ФЗ) и реклама (38-ФЗ ст. 18). Без первого
   не пишем вообще, без второго — только сообщения по записи. Рекламные отправки идут через проверку модуля Consents.

## Последствия
- Сайт и сервер должны стоять на одном компьютере (так и есть в клинике). Если их разнесут — нужен вход по JWT из ADR-0010.
- В журнале сервера все действия панели идут от `web-panel`; кто именно из сотрудников — пока только в журнале согласий.
- ADR-0010 §2 (перенос учёток в `Users`, роли) остаётся целью; когда его сделают, ключ панели убирается.
- MAUI-программа администратора в клинике больше не нужна.
