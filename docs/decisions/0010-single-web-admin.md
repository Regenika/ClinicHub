# ADR-0010. Одна веб-админка и общие учётные записи

- Статус: **принято** (2026-10-24, решение Свята)
- Развивает [ADR-0005](0005-admin-ui.md) и ADR-0007 §5.

## Контекст
Сейчас у системы две админки с разными учётными записями:
- **веб-админка сайта** (`ClinicHub.Web`, `/admin`) — редакторы из таблицы `site.Editors`, вход по куке;
- **MAUI-админка рассылок** (`ClinicHub.Admin`) — пользователи сервера `Users` (роли Admin, Operator), вход по JWT.

Сотрудникам клиники неудобно держать две программы и два пароля. Кроме того, экраны визитов и сценариев (PLAN 1.12) решено делать только в вебе (ADR-0005).

## Решение
1. **Одна админка — веб-админка в `ClinicHub.Web`** (`/admin`). В ней разделы «Сайт» (страницы, медиатека, настройки, каталог) и «Рассылки и пациенты» (заявки, пациенты, телефоны и подключение по QR, авто-правила, настройки отправки, визиты, сценарии, согласия). Меню общее, переход между разделами — обычные ссылки.
2. **Одни учётные записи — пользователи сервера (`ClinicHub.Api`, таблица `Users`).** Добавляется роль `Editor` (только раздел «Сайт»). Права: Admin — всё; Operator — рассылки, пациенты, визиты, без настроек и сценариев; Editor — только сайт. Таблица `site.Editors` переносится в `Users` одноразовой миграцией с теми же логинами (хеши паролей несовместимы → пароль задаётся заново, администратор видит список перенесённых), затем удаляется.
3. **Как веб-админка получает данные:**
   - данные сайта (схема `site`) — напрямую через `SiteDbContext`, как сейчас;
   - всё остальное — **только через HTTP API сервера** (`/api/...`) от имени вошедшего пользователя. Веб-админка не лезет в таблицы сервера напрямую: правила (согласия, окно отправки, история цен) остаются в одном месте.
   - Вход: форма `/admin/login` → `POST /api/auth/login` → JWT хранится на сервере сайта в зашифрованной куке (HttpOnly, SameSite=Strict); в браузер JWT не попадает. Адрес сервера — настройка `Api:BaseUrl`.
4. **Каталог услуг и врачей — только на сервере** (модуль Catalog, #26). Временный каталог сайта (`site.Catalog*`, `site.CatalogPriceChanges`) убирается, сайт и админка читают и правят каталог через `/api/catalog`.
5. **MAUI-админка** работает, пока веб-админка не повторит её функции. На это время в ней есть кнопка «Открыть веб-админку». Когда паритет достигнут, MAUI-админка архивируется (ADR-0005).

## Последствия
- Сайт зависит от работающего сервера `ClinicHub.Api` для админки и каталога. Публичные страницы при недоступном сервере показывают последнюю закешированную версию каталога, а не ошибку.
- Задачи: проверка и приём ветки сайта, общий вход, перенос каталога, перенос разделов MAUI — отдельные Issue на AlDanosAl.
