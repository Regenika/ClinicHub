# Выбор МИС — первичное исследование

> Статус: **черновик для короткого списка**, 2026-10-16. Данные с каталогов (a2is, crmindex, medesk) и сайтов вендоров;
> цены и условия **обязательно уточнять на демо** — каталоги часто устаревают.

## Что нам важно (в порядке веса)

1. **Удобство для врачей-косметологов и администраторов** — шаблоны осмотров для косметологии, фото до/после в карте, информированные согласия, абонементы/курсы процедур. Если врачам неудобно — проект провалится, сколько бы API ни было.
2. **Штатная интеграция с ПроДокторов** (расписание + онлайн-запись) — чтобы не писать её самим.
3. **Открытый API и/или вебхуки** — пациенты, записи, свободные слоты, создание записи. Без этого не будет онлайн-записи на сайте и напоминаний.
4. **Онлайн-запись (виджет)** — тогда Dikidi можно отключить.
5. **Где хранятся данные**: облако вендора в РФ допустимо по 152-ФЗ; локальная установка — плюс с учётом нашего курса на независимость от внешних ЦОД, но минус в администрировании (это ляжет на Свята).
6. Импорт пациентов из Excel, цена, ЕГИСЗ (если клиника обязана подключаться).

## Dikidi
- Это система записи для сферы услуг, не МИС: медкарт и медицинских документов в ней нет.
- **Официального публичного API нет.** Есть неофициальные обёртки, собранные реверс-инжинирингом, с входом по телефону и паролю (например, `dikidi-api-client` на PyPI в статусе beta). Использовать их можно только как временный мост на чтение — без гарантий и, возможно, вразрез с условиями сервиса.
- Вывод: после внедрения МИС онлайн-запись переносится в неё, а Dikidi отключается или остаётся только витриной.

## Вопросы для демо (копировать в письмо вендору)
1. Есть ли шаблоны карт/протоколов для косметологии, фото до/после в карте пациента, электронные информированные согласия?
2. Интеграция с ПроДокторов: что синхронизируется (расписание, запись, отзывы?), стоимость?
3. API: документация публичная? Какие сущности (пациенты, записи, слоты, услуги, врачи)? Есть ли вебхуки на создание/изменение записи? Лимиты? Стоимость доступа?
4. Виджет онлайн-записи для сайта — можно ли встроить или делать свою форму через API?
5. Где хранятся данные (ЦОД в РФ?), есть ли локальная установка, как делаются бэкапы и выгрузка всех данных при уходе от вендора?
6. Импорт пациентов из Excel/CSV — формат, кто делает?
7. Встроенные SMS/мессенджер-рассылки — есть ли (не будет ли конфликта/дублирования с нашим хабом)?
8. Цена для клиники: N врачей, M администраторов; стоимость внедрения и обучения.
9. ЕГИСЗ/ФРМО — нужно ли клинике и поддерживается ли?

## Следующий шаг
Запросить демо у **MEDODS, Renovatio и ещё одного** (Medmis или Клиентикс) → заполнить таблицу ответами → решение руководителя → ADR «Выбор МИС».
Готовое письмо с вопросами (в том числе про прайс и локальную установку): [MIS-DEMO-REQUEST.md](MIS-DEMO-REQUEST.md).

Как интегрируемся, когда МИС выбрана: **только через API**, даже при локальной установке, без записи напрямую в её базу (ADR-0002, ADR-0007 §2).
