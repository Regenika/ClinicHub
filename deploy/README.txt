УСТАНОВКА CLINICHUB НА КОМПЬЮТЕР КЛИНИКИ — ВСЁ НА ОДНОЙ СТРАНИЦЕ
=================================================================

Как устроено
------------
  Компьютер клиники:  сервер рассылок (служба «ClinicHub API», порт 5112)
                      + сайт и админка (служба «ClinicHub Web», порт 8080).
  Телефон с SmsAgent: в той же Wi-Fi сети клиники (не гостевой) — отправляет SMS.
  База данных:        SQL Server у Свята дома; доступ с компьютера клиники — по VPN или туннелю
                      (настраивается отдельно, порт 1433 в интернет не открываем).
  Резервные копии:    на компьютере у Свята (deploy\db\backup-setup.ps1), на компьютере клиники их нет.

Что подготовить заранее
-----------------------
- Архивы ClinicHub-Api-<дата>.zip и ClinicHub-Web-<дата>.zip. Собираются на компьютере разработчика из репозитория:
    powershell -ExecutionPolicy Bypass -File deploy\api\build-package.ps1
    powershell -ExecutionPolicy Bypass -File deploy\web\build-package.ps1
  (готовые архивы — в папке artifacts).
- От Свята: адрес SQL Server, логин и пароль SQL Server для базы ClinicHub; работающий VPN или туннель до него.
- Android-телефон с SIM-картой клиники. Приложение «ClinicHub SMS» ставится на шаге 5 по ссылке — компьютер для этого не нужен.

Шаги
----
1. Компьютер клиники: Пуск → «Параметры» → «Система» → «Питание»: «Переводить в спящий режим» — «Никогда».
   Гибернацию выключить: PowerShell от администратора → powercfg /hibernate off
   Сеть Wi-Fi клиники в Windows — «Частная»: «Параметры» → «Сеть и Интернет» → Wi-Fi → свойства сети → «Частная сеть».

2. Проверить доступ к базе: VPN или туннель включён, адрес SQL Server отвечает (спросить у Свята, как проверить).

3. Сервер: распаковать ClinicHub-Api-<дата>.zip → install.cmd → ответить на вопросы (сервер базы, база ClinicHub,
   логин, пароль; Dikidi — пропустить). В конце — «Готово» и «База данных: подключена».
   Записать адрес для телефонов из последних строк (http://<IP>:5112).

4. Сайт: распаковать ClinicHub-Web-<дата>.zip → install.cmd. Откроется страница «Подключение к базе данных»:
   тот же сервер, база ClinicHub, тот же логин и пароль → «Проверить и сохранить».
   Сайт: http://localhost:8080, админка: http://localhost:8080/admin.

5. Телефон: в браузере телефона открыть https://github.com/Regenika/ClinicHub/releases/latest →
   скачать ClinicHub-SmsAgent-<версия>.apk → установить (разрешить установку из браузера).
   Android 13 и новее: «Настройки» → «Приложения» → «ClinicHub SMS» → ⋮ → «Разрешить ограниченные настройки».
   Если стоит старая сборка «ClinicHub.SmsAgent» (фиолетовый значок .NET) — удалить её (новая встанет рядом отдельным приложением).
   Подключить телефон к Wi-Fi клиники → открыть «ClinicHub SMS» → «Подключиться» (сервер найдётся сам),
   разрешить SMS и уведомления.
   Если не нашёлся — ввести адрес из шага 3 вручную. Проверка: в браузере телефона http://<IP>:5112/api/health → "ok".
   На компьютер клиники программа администратора (MAUI) не ставится: её запускают на ноутбуке разработчика
   в той же сети и в окне входа указывают адрес сервера http://<IP>:5112. На вкладке «Телефоны» телефон
   должен быть «на связи». (Потом её заменит веб-админка, ADR-0010.)

6. Тестовая SMS: в программе администратора — заявка «Сервисное» ТОЛЬКО на свой номер → «Одобрить» → SMS пришла.

ЧЕК-ЛИСТ ПРОВЕРКИ (за один визит)
--------------------------------
[ ] 1. Установлены сервер и сайт, у каждого своя служба: Пуск → «Службы» → «ClinicHub API» и «ClinicHub Web»
       — «Выполняется», тип запуска «Автоматически (отложенный запуск)».
[ ] 2. Перезагрузка компьютера: обе службы поднялись сами (без входа в Windows), http://localhost:5112/api/health
       — "status":"ok","database":"ok"; сайт http://localhost:8080 открывается.
[ ] 3. Сайт открывается с другого компьютера или телефона в сети клиники: http://<IP компьютера>:8080
[ ] 4. Телефон с «ClinicHub SMS» в ТОЙ ЖЕ Wi-Fi сети, что и компьютер (не в гостевой), подключён, «на связи».
[ ] 5. Тестовая SMS ушла и пришла — ТОЛЬКО на свои номера. Пациенты в базе — выдуманные.
       Реальную таблицу пациентов не загружаем, пока нет импорта (PLAN 1.3) и согласий от пациентов.
[ ] 6. Сон и гибернация выключены (шаг 1).
[ ] 7. На компьютере Свята резервная копия базы появилась в папке копий (backup.log — «Готово и проверено»).
[ ] 8. Временно выключить VPN: сервер и сайт не упали, в журнале «Нет связи с базой данных…»;
       включить VPN — через полминуты всё снова работает.

Если что-то не так
------------------
- Сервер: C:\ClinicHub\Api\logs\clinichub.log, http://localhost:5112/api/debug/state (только с этого компьютера).
- Сайт:   C:\ClinicHub\Web\logs.
- Ошибки обеих служб — «Просмотр событий» → «Журналы Windows» → «Приложение», источники ClinicHub.Api и ClinicHub.Web.
Подробности: deploy\api\README.txt, deploy\web\README.txt, восстановление базы — deploy\db\RESTORE.txt.
