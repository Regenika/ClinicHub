СЕРВЕР РАССЫЛОК (ClinicHub.Api) — УСТАНОВКА НА КОМПЬЮТЕР КЛИНИКИ
================================================================

Полная пошаговая установка (сервер, сайт, телефон) и чек-лист — в файле deploy\README.txt репозитория.
Здесь — только про сервер.

Перед установкой
----------------
- База данных — на SQL Server на ДРУГОМ компьютере (у Свята), доступ к нему — по VPN или туннелю.
  Настройте доступ заранее: адрес сервера базы должен открываться с этого компьютера.
  SQL Server и LocalDB на компьютер клиники НЕ ставим.
- Нужны: адрес SQL Server, имя базы (ClinicHub), логин и пароль SQL Server. Их даёт Свят.

Установка
---------
1. Распакуйте архив ClinicHub-Api-<дата>.zip целиком в любую папку.
2. Дважды щёлкните install.cmd и разрешите запуск от имени администратора.
3. Ответьте на вопросы: сервер базы, база, логин, пароль. Установщик проверит подключение.
   Если базу сейчас не видно (VPN не поднят), можно продолжить — сервер будет подключаться сам каждые 30 секунд.
   Dikidi можно пропустить.
4. В конце окно покажет:
     - адрес сервера на этом компьютере:  http://localhost:5112  (для сайта и программы администратора);
     - адреса для телефонов:              http://<IP этого компьютера>:5112.

Сервер работает службой Windows «ClinicHub API»: запускается сам при включении компьютера, без входа в Windows.
Если упадёт — Windows перезапустит его через минуту. Пуск → «Службы» → «ClinicHub API».

Пароль и логин базы хранятся на этом компьютере в зашифрованном виде (C:\ClinicHub\Api\config\secrets.dat),
прочитать их может только служба сервера. Сменить подключение к базе или ключи Dikidi:
  в папке установщика откройте PowerShell от администратора и выполните
  powershell -ExecutionPolicy Bypass -File install.ps1 -ChangeSecrets

Порт 5112 открыт только для частной и доменной сети и только для адресов этой же сети (телефоны по Wi-Fi).
В общественной сети порт закрыт. Если Wi-Fi клиники в Windows отмечен как общественный, установщик предупредит
и покажет команду, которая это исправит. VPN до базы частной делать не нужно.
Другой порт:  install.cmd 5113

Первый вход в программу администратора: если база пустая, сервер создаёт администратора admin со случайным
паролем и пишет его в журнал C:\ClinicHub\Api\logs\clinichub.log (строка «Создан первый администратор»).
Если база уже рабочая (общая с другим компьютером) — входите своим логином.

Если сервер не работает
-----------------------
- На этом компьютере откройте http://localhost:5112/api/health — должно быть "status":"ok".
  "database":"waiting" — нет связи с базой; причина: http://localhost:5112/api/debug/state
- Журнал: C:\ClinicHub\Api\logs\clinichub.log. Ошибки — также в «Просмотр событий» → «Журналы Windows» →
  «Приложение», источник ClinicHub.Api. Эти файлы пришлите разработчикам.

Обновление
----------
Распакуйте новую версию и снова запустите install.cmd — секреты и журнал сохранятся, вопросы задаваться не будут.
Автообновление с GitHub (демо-компьютеры): deploy\web\auto-update.ps1 -Register — обновляет и сайт, и сервер,
если они установлены.

Удаление
--------
Дважды щёлкните uninstall.cmd. Удаляются служба, правила брандмауэра и папка C:\ClinicHub\Api (с секретами).
База данных и её резервные копии не трогаются — они на компьютере с SQL Server.
